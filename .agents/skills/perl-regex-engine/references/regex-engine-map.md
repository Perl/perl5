# Regex Engine Map

## Core Files

- `regcomp.c`: parser/compiler, node emission, compile-time setup.
- `regexec.c`: executor, matching states, backtracking, `regtry`.
- `regcomp_study.c`: optimizer/study, start classes, substring checks.
- `regcomp_trie.c`: trie construction and related optimizations.
- `regcomp_invlist.c`: inversion-list helpers.
- `regcomp_debug.c`: regex debug dumps and properties.
- `regcomp.h`, `regcomp_internal.h`, `regexp.h`, `op_reg_common.h`, `reginline.h`: shared structs, flags, and macros.
- `ext/re/re.pm`, `ext/re/Makefile.PL`, `ext/re/re_top.h`: user-facing `re` pragma, debug controls, and the dual-build path where `regcomp.c` and `regexec.c` are copied to `ext/re/re_comp.c` and `ext/re/re_exec.c`.
- `pod/perlreapi.pod`: public regex plugin API, including callbacks, `regexp_engine`, and `REGEXP`.

## Generated Files

- `regnodes.h`: generated from `regcomp.sym`, `op_reg_common.h`, and `regexp.h` by `regen/regcomp.pl`.
- `pod/perldebguts.pod`: includes a generated regex-node table.
- `regcharclass.h`: generated by `regen/regcharclass.pl`.
- `charclass_invlists.inc`, `regexp_constants.h`, `uni_keywords.h`: generated through Unicode/invlist regen paths.

Use `make regen` for full regeneration and `make regen_headers` for header-focused regeneration; do not call `regen.pl` directly. Some regex-related generators require the just-built Perl, so run `./perl -Ilib t/porting/regen.t` after regeneration.

## Regnode Guardrails

Edit opcode/state definitions in `regcomp.sym`, not `regnodes.h`. Preserve order-sensitive families such as `BOUND/NBOUND`, `POSIX*`, `EXACTF*`, and `ANYOF*`.

Useful search:

```sh
rg -n "order.*important|Must be sequential|must immediately follow|EXACTF|ANYOF|POSIX|BOUND" regcomp.sym regcomp.c regexec.c
```

Understand `REGNODE_AFTER` versus `regnext` before changing node layout or optimizer jumps. `pod/perlreguts.pod` explains this distinction.

## Debug Workflow

- `use re 'debug'`, `use re 'debugcolor'`, and `use re qw(Debug ...)` expose high-level regex debug output.
- `-DDEBUGGING` enables lower-level `-Dr` paths.

Search debug plumbing:

```sh
rg -n "DEBUG_[A-Z_]+_r|DECLARE_AND_GET_RE_DEBUG_FLAGS|regdump|regprop|PERL_RE_BUILD_DEBUG" regcomp*.c regexec.c ext/re
```

## Tests

- Primary tests: `t/re/`.
- Table-driven cases: `t/re/re_tests`, consumed by `t/re/regexp.t`.
- Richer behavior: `t/re/pat.t`, `t/re/pat_advanced.t`, `t/re/pat_rt_report.t`, `t/re/subst.t`.
- Focused risk tests: `t/re/anyof.t`, `t/re/opt.t`, `t/re/charset.t`, `t/re/regexp_notrie.t`.
- Thread variants: `_thr.t` files.
- Unicode properties: `t/re/uniprops*.t`.
- API-level: `ext/re/t/*`, `ext/XS-APItest/t/callregexec.t`, `ext/XS-APItest/t/regex_global_pos.t`.
- Tooling visibility: `lib/B/Deparse.t` and `ext/B/t/*` when regex code blocks, optrees, or op compaction are involved.

Useful test commands:

```sh
make test_harness TEST_ARGS='re/*.t ../ext/re/t/*.t'
cd t && ./perl -I../lib harness re/foo.t
cd t && ./perl -I../lib re/foo.t
```

Find `re_tests` format:

```sh
rg -n "Column 1|expected result|re_tests|If you want to add" t/re/regexp.t t/re/re_tests
```

## High-Risk Areas

Unicode/UTF-8 versus bytes, `/d /u /a /aa /l`, locale and UTF-8 locale behavior, EBCDIC, multi-character folds, `EXACTF*`, `ANYOF*`, inversion lists, tries, synthetic start classes, `check_substr`, `check_utf8`, `GPOS`, captures, branch reset, `(?{})`, `(??{})`, recursion, lookbehind, regex sets, and threaded cloning.

Risk search:

```sh
rg -n "TRICKYFOLD|multi-char|EXACTF|ANYOF|ANYOFL|ANYOFD|locale|UTF-8|utf8|EBCDIC|invlists|branch reset|logical_nparens|parno_to_logical|lookbehind|GPOS|regex_sets|TRIE|stclass|check_utf8|check_substr" regcomp*.c regexec.c regcomp*.h regexp.h t/re
```

For debug code or helper functions, check the `ext/re` dual-build naming and visibility rules before adding new symbols. When removing or replacing externally visible regex variables or helpers, check `embed.fnc`, export generation, XS/API users, and archaeology evidence for outside-core usage.
